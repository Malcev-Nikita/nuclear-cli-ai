# Nuclear CLI AI

Голосовой ассистент для [Nuclear](https://github.com/nukeop/nuclear) — аналог
«Яндекс станции» на своём ПК. Текущий этап: **2 — голосовые команды**
(текстовый режим: `python main.py --text`).

```
голос → VAD → faster-whisper (STT) → «фраза начинается с "Игорь"?»
     → regex-роутер (мгновенно) → LLM (Ollama, tool calling) → Nuclear MCP → плеер
```

## Требования

- Nuclear с включённым MCP (`Settings → Integrations → Enable MCP Server`)
  и плагином puer (metadata-провайдер выбран в Sources);
- [Ollama](https://ollama.com/download) + модель: `ollama pull qwen3:1.7b`;
- Python 3.10+.

## Запуск (Windows, PowerShell)

```powershell
cd nuclear-cli-ai
python -m pip install -r requirements.txt
python main.py                     # голосовой режим
python main.py --text              # текстовый REPL (без микрофона и озвучки)
python main.py --devices           # список микрофонов
python main.py --meter             # уровень микрофона против порога VAD (тюнинг)
```

Голосовой режим: скажите **«Мага, включи нирвану»** — фразы без имени
игнорируются. Исключения: короткие управляющие команды («стоп», «пауза»,
«дальше», «громче»…) работают и без имени. Просто «Мага!» — ассистент скажет
«Слушаю», и несколько секунд команда принимается без имени. Первый запуск
скачивает модель whisper (~1.6 ГБ для `large-v3-turbo`) и голос (~60 МБ).

Примеры команд:

| Команда | Что происходит |
| --- | --- |
| `включи нирвану` | LLM → `play_artist` → топ-треки исполнителя в очередь |
| `поставь smells like teen spirit` | LLM → `play_track` → первый найденный трек |
| `включи альбом nevermind` | без LLM (тип назван явно) → альбом целиком |
| `плейлист rock classics` | без LLM → сначала свои плейлисты, потом YT Music |
| `поставь песню Х` / `включи группу Х` | без LLM → трек / исполнитель |
| `включи избранное` / `любимые треки` | без LLM → все избранные треки в очередь |
| `дальше`, `пауза`, `громче`, `что играет`, `в избранное` | без LLM, мгновенно |
| `перемотай на 30 секунд вперёд/назад` / `сначала` | без LLM → Playback.seekTo |
| `какая погода` / `погода в казани` | без LLM → Open-Meteo (интернет, без API-ключа) |
| `погода завтра` / `на выходных` / `будет ли дождь в пятницу` | прогноз на день недели, выходные, послезавтра |
| `включи что-нибудь` | избранное вперемешку (нет — случайный плейлист) |
| `добавь в очередь Х` | дописать трек, не прерывая текущий |
| `повтор` / `повтори трек` / `перемешай` | режимы очереди Nuclear |
| `найди/загугли Х` или вопрос о фактах | поиск DuckDuckGo → краткий пересказ моделью |
| `сколько времени` / `какое сегодня число` | без LLM, мгновенно, локальные часы |
| `запиши/запомни Х`, `прочитай заметки` | заметка в файл `public/notepad/`; `удали последнюю заметку` |
| `что я записывал про Х` | поиск по заметкам |
| `таймер на 10 минут`, `напомни через час Х`, `разбуди в 7` | таймеры/будильники (переживают перезапуск), `какие таймеры`, `отмени всё` |
| `сколько я проработал` (сегодня/вчера/за неделю/26 июня) | учёт времени Битрикс24 (нужен вебхук в `config.local.toml`) |
| `включи с ютуба Х` / `включи видос Х` | обычный YouTube (видосы/миксы/подкасты), звук в Nuclear |

## Конфиг

Все настройки — в **`config.toml`** (подключения, имя ассистента, VAD, whisper,
голос, погода), у каждой — комментарий, что на что влияет. Личные значения
(имя, город, голос) кладите в **`config.local.toml`** (скопируйте
`config.local.toml.example` и оставьте только нужное) — он в `.gitignore`,
обновления проекта его не тронут. Приоритет: env-переменные →
`config.local.toml` → `config.toml`:

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `NUCLEAR_MCP_URL` | `http://127.0.0.1:8800/mcp` | адрес из Settings → Integrations |
| `OLLAMA_URL` | `http://127.0.0.1:11434` | можно указать другой хост (напр. с Raspberry Pi на ПК) |
| `OLLAMA_MODEL` | `qwen3:1.7b` | побольше: `qwen3:4b`; на Pi: `qwen3:0.6b` |
| `OLLAMA_KEEP_ALIVE` | `30m` | сколько держать модель в памяти |
| `ASSISTANT_NAMES` | `игорь` | имена через запятую: `игорь,гарик,ассистент` |
| `ASSISTANT_LORE` | пусто | характер/лор для болтовни («ты дерзкий, но добрый…») |
| `WHISPER_MODEL` | `large-v3-turbo` | на слабой машине: `small` (хуже имена артистов) |
| `WHISPER_DEVICE` | `auto` | `cuda` / `cpu` (auto пробует cuda, падает на cpu) |
| `MIC_DEVICE` | системный | индекс или часть имени из `main.py --devices` |
| `PIPER_VOICE` | `ru_RU-irina-medium` | голос озвучки ([примеры](https://rhasspy.github.io/piper-samples/)); `""` = без озвучки |
| `TTS_SPEED` | `1.5` | темп речи (1.0 = обычный) |
| `DUCK_VOLUME_PCT` | `25` | до скольких % приглушать музыку на время речи (0 = не трогать) |
| `WEATHER_CITY` | по IP | город для «какая погода» без уточнения |
| `B24_WEBHOOK` | пусто | вебхук Битрикс24 для «сколько я проработал» (секрет!) |

```powershell
$env:OLLAMA_MODEL = "qwen3:1.7b"; python main.py
```

## Структура

```
main.py           # точка входа (сборка сервисов, навыков, агента; оба режима)
config.toml       # настройки; config.local.toml — личные (в .gitignore)
src/config.py     # загрузчик настроек
src/core/         # ядро: wake-логика, агент, тексты — не знает о внешнем мире
src/services/     # адаптеры: Nuclear MCP, Ollama, Open-Meteo, DDG, YouTube
src/audio/        # микрофон+VAD, whisper, piper (barge-in)
src/skills/       # навыки: playback, music, favorites, youtube, weather,
                  #         clock, notes, search — правила роутера + инструменты LLM
tests/            # pytest: uv run --with requests --with pytest -m pytest tests
```

Новая способность = новый класс в `src/skills/` (правила + инструменты + логика)
и одна строчка в сборке `main.py`.

## Архитектура и решения

- **Роутер до LLM**: частые команды (пауза/дальше/громче/лайк) и команды с явно
  названным типом («альбом Х», «плейлист Х», «песню Х», «группу Х») обрабатываются
  regex'ами без модели — ноль латентности; на Raspberry Pi это большинство команд.
- **Прогрев Ollama при старте**: модель грузится в память в фоне, первая команда
  не платит холодный старт.
- **Узкие инструменты вместо сырого MCP**: модель выбирает из 18 понятных действий
  (`play_track`, `play_artist`, ...), а не исследует API Nuclear через
  `list_methods`/`describe_type` (это экономит 3-4 раунда на команду).
- **Один вызов LLM на команду**: результат инструмента озвучивается напрямую,
  без второго круга через модель.
- `think: false` для qwen3 — рассуждения дают +2-5 секунд латентности.
- Шкала громкости Nuclear не задокументирована — определяется по текущему значению.
- **Wake word без отдельной модели**: у openWakeWord нет готовой модели под
  русское имя. Вместо неё whisper распознаёт каждую фразу, а ассистент реагирует
  только на фразы, начинающиеся с имени (нечёткое сравнение: «Егорь»/«Игор»
  тоже срабатывают; побочно срабатывают и падежи — «Игоря»).

**Уточнения к прошлой команде**: «сколько я отработал вчера» → «а за
позавчера?», «какая погода» → «а в Москве?». Работают 3 минуты после ответа и
только для навыка, который отвечал последним.

**Таймеры и будильники** хранятся в `public/reminders.json` и переживают
перезапуск. Срабатывают в тишине между фразами (проверка раз в полсекунды):
ассистент бипает и проговаривает — «Таймер! Время вышло», «Напоминаю: выключить
духовку», «Подъём! 7 часов». Пропущенное больше чем на 12 часов не выкрикивается.

Ответы озвучиваются голосом `piper` **потоково** — фразы синтезируются по
предложениям и звучат по мере готовности, поэтому длинный ответ начинается
почти сразу (модель голоса ~60 МБ скачивается при первом запуске в `voices/`);
после каждой реплики микрофонный буфер
сбрасывается, чтобы ассистент не слушал сам себя. На время речи **музыка
приглушается** до `duck_volume` (25%) и возвращается на прежний уровень —
ответ слышно поверх трека, а тихое эхо делает перебивание надёжнее. Говорящего ассистента можно
**перебить голосом** — начните говорить поверх него, и он замолчит; «замолчи» /
«заткнись» (без имени) обрывают речь, не трогая музыку.
